# 备份前数据一致性协调记录

**日期：2026 年 9 月 18 日**

## 起因

完整备份预检发现 MySQL `meetings` 表与 `data/meetings` 顶层目录不一致：数据库中有 1 条会议记录，文件系统中有 2 个会议目录，其中 1 个目录没有对应数据库记录。备份工具因此拒绝产出可能无法解释或无法完整恢复的归档。

## 授权与处理原则

负责人明确允许将无数据库记录的历史会议目录移动到独立隔离区。处理遵循：

- 不删除文件；
- 不读取或输出会议内容；
- 移动前验证源路径和目标路径均位于 `D:\MeetingMind\data`；
- 拒绝符号链接、重解析点和目标冲突；
- 失败时尝试把已移动目录回滚到原位置；
- 移动后生成仅含相对路径、大小和 SHA-256 的清单。

## 执行结果

执行脚本：

```powershell
.\scripts\isolate_orphaned_meeting_directories.ps1 `
  -IsolationName '20260918-pre-backup-reconciliation'
```

结果：

- 隔离目录：`data/orphaned-meetings/20260918-pre-backup-reconciliation`；
- 隔离目录数：1；
- 文件数：3；
- 未删除任何数据；
- 协调后 MySQL 会议记录数与 `data/meetings` 目录数均为 1；
- 孤立目录数：0；缺失目录数：0。

## 完整恢复复验

保留归档：

```text
data/backups/meetingmind-20260918-post-reconciliation.zip
```

验证结果：

- manifest 与所有 SHA-256：通过；
- MySQL dump：通过；
- 隔离文件恢复：通过；
- 临时隔离数据库导入：通过；
- 恢复数据库会议 ID 与文件目录：一致；
- 临时数据库和演练目录：已清理；
- 运行监控：`healthy`。

隔离历史目录仍被视为敏感用户数据，不得未经单独确认删除。
