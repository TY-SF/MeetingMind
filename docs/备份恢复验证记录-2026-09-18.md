## 真实隔离恢复演练

使用当前数据库中的一个已登记会议目录构造临时测试数据根目录，未修改当前 `data/meetings`，执行：

1. 真实 `mysqldump --single-transaction`；
2. 生成 ZIP 归档；
3. `verify` 校验数据库 dump 和会议文件 SHA-256；
4. 恢复到临时隔离文件目录；
5. 导入临时隔离 MySQL 数据库；
6. 查询隔离数据库会议 ID，与恢复文件目录核对；
7. 删除本次临时隔离数据库和临时恢复目录。

结果：归档验证通过，隔离文件恢复通过，隔离数据库会议 ID 核对通过；未输出转录内容、模型响应、令牌或密码。

## 当前发布阻塞项

对完整当前运行目录执行备份预检时，发现 `data/meetings` 顶层目录与 MySQL `meetings` 表不一致。工具拒绝创建归档，这是预期的安全行为：如果静默忽略多出的目录，恢复后可能出现无法解释的用户文件；如果只备份数据库，又可能丢失本地音频。

本次未删除、移动或覆盖任何源目录。负责人需要先确认不一致目录是否为历史测试数据，再决定将其纳入对应数据库、隔离归档，或在独立确认后清理。解决前，完整数据备份和发布门禁仍为未通过。
