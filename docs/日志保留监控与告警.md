# 第八阶段：日志保留、运行监控与本地告警边界

**实现日期：2026 年 9 月 18 日**

## 第一性原理

可观测性不能只回答“有日志”，而要同时满足：

1. **有限**：日志不能无限增长直至占满磁盘；
2. **可关联**：HTTP 请求可以通过 `X-Request-ID` 定位；
3. **不泄密**：不记录请求体、完整转录、模型原始响应、Bearer Token、API Key 或数据库密码；
4. **可判定**：监控必须给出机器可读状态和稳定退出码；
5. **可行动**：状态变化要形成告警事件，但不能把业务内容放进告警；
6. **不夸大**：本地告警文件不是外部通知系统，备份文件存在也不等于恢复门禁已经通过。

## 有界结构化日志

API 与 RQ 任务使用独立 JSONL 文件，避免多个进程争用同一轮转文件：

- `data/logs/api.jsonl`；
- `data/logs/worker.jsonl`。

默认每个活动文件最大 10 MiB，保留 5 个轮转文件，可通过以下变量调整：

```text
MEETINGMIND_LOG_MAX_BYTES=10485760
MEETINGMIND_LOG_BACKUP_COUNT=5
```

日志格式包含 UTC 时间、级别、logger、事件名、请求 ID 和有限运行指标。格式化层会遮盖：

- `Authorization: Bearer ...`；
- `OPENAI_API_KEY`、`HF_TOKEN`、MySQL 密码和部署 Token 形式的赋值；
- URL 中的用户名/密码；
- 名称包含 `token`、`password`、`secret`、`credential`、`api_key` 的额外字段。

遮盖是最后一道防线，不代表可以主动把转录或模型响应传给 logger。应用代码仍然禁止记录请求体、完整转录和模型原始输出。

`scripts/start_api_background.ps1` 和 `scripts/start_rq_worker_background.ps1` 使用隐藏后台窗口启动服务。API 访问日志由 MeetingMind 中间件记录，宿主标准输出不再写入无限增长文件；宿主错误日志在启动时按 10 MiB、最多 4 个历史文件轮转。Docker MySQL、Redis 和 Caddy 的 `json-file` 日志均配置为 `10m × 5`。

## 运行监控

执行本机 HTTPS 检查：

```powershell
.\scripts\check_operations.ps1 -TrustLocalCaddyCA
```

生产环境使用可信证书时不要传 `-TrustLocalCaddyCA`。跳过证书验证被硬性限制在 `localhost`、`127.0.0.1` 和 `::1`，监控 URL 禁止携带用户名、密码、查询参数或片段，并禁用 HTTP 重定向，避免访问令牌被转发到其他地址。

检查项：

- API 存活；
- MySQL 就绪；
- Redis/RQ Worker 和队列状态；
- 数据盘剩余空间；
- 最新备份归档候选文件的时效；
- API/Worker 结构化日志是否存在。

输出文件：

- `data/monitoring/latest.json`：最新完整报告；
- `data/monitoring/state.json`：当前状态与最近变化时间；
- `data/monitoring/alerts.jsonl`：仅在状态变为 `warning` 或 `critical` 时追加的本地告警事件。

退出码：

- `0`：`healthy`；
- `1`：`warning`；
- `2`：`critical` 或监控自身无法执行。

报告和告警只包含检查名称、状态与运行指标，不包含访问令牌、会议标题、转录或模型内容。

## 发布与调度边界

`pre_release_check.ps1` 默认执行 MySQL 与会议文件的一致性备份和隔离恢复。开发者只有在明确知道该门禁尚未完成时才可使用：

```powershell
.\scripts\pre_release_check.ps1 -SkipBackupRestore
```

该参数会产生警告，不应被解释为生产发布通过。

本地 `alerts.jsonl` 提供稳定的告警事件接口，但**尚未接入邮件、短信、PagerDuty、Teams 或其他外部通知渠道**。目标部署必须由运维系统按退出码或告警文件接入通知，并定义负责人、值班时段、升级路径和恢复确认流程。

## 当前验证结论

2026 年 9 月 18 日本机验证：

- 后端测试：`70 passed`；
- API、MySQL、Redis/RQ Worker、磁盘和结构化日志检查通过；
- 监控总状态为 `warning`，唯一警告是尚无满足完整数据一致性门禁的备份归档；
