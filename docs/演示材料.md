# MeetingMind 演示材料与讲解脚本

**版本：第七阶段本地单机发布候选｜更新：2026 年 9 月 14 日｜建议时长：8–10 分钟**

本材料用于演示已实现能力。它刻意区分“已验证能力”“配置依赖”和“尚未解决的生产化边界”，避免把计划、Mock 数据或页面文案当作真实能力。

## 1. 演示目标

在一次完整演示中证明以下事实：

1. 音频保存在本机，并经过 FFmpeg、WhisperX 对齐与 pyannote 自动说话人分离；
2. 处理进度和阶段耗时来自持久化任务事件，而不是前端模拟；
3. 说话人原始标签可人工映射为姓名；
4. AI 分析由用户主动触发，且可以人工审核、查看差异；
5. Markdown 和 Outlook 兼容 ICS 均由后端真实生成；
6. 失败时保留有效转录并清晰标记降级，不伪造“已完成”。

第七阶段还应展示：Redis + RQ 任务状态、Worker 健康检查、真实任务中断后的稳定错误码和重试，以及删除后的数据清理结果。

## 2. 演示前准备（5 分钟）

1. 确认 MySQL 8 已启动，执行：

   ```powershell
   Invoke-RestMethod http://127.0.0.1:8000/api/v1/health/ready
   ```

   预期：`status` 为 `ready`。

2. 运行发布前检查：

   ```powershell
   cd D:\MeetingMind
   .\scripts\pre_release_check.ps1
   ```

3. 启动或确认后端：

   ```powershell
   cd D:\MeetingMind
   $env:PYTHONPATH = "D:\MeetingMind\backend"
   $venv = (& .\scripts\resolve_runtime_venv.ps1 -RequireAudio | Select-Object -Last 1).Trim(); & (Join-Path $venv 'Scripts\python.exe') -m uvicorn app.main:app --app-dir backend --reload
   ```

4. 在另一个终端启动前端：

   ```powershell
   cd D:\MeetingMind\frontend
   npm run dev
   ```

5. 使用一段**已获允许**的中文多人会议录音。不要在演示环境中展示机密会议、Token、数据库密码或 `.env` 文件。

## 3. 主演示脚本

| 时间 | 操作 | 建议讲解 | 可观察证据 |
| --- | --- | --- | --- |
| 0:00–0:45 | 打开会议列表与新建会议页 | “系统本地优先。上传后先进行本地处理；AI 不会在上传时自动调用。” | 上传页的数据边界说明。 |
| 0:45–1:30 | 填写标题、时间、参会人、背景并上传 MP3/WAV/M4A | “参会人用于会议元数据，不强制作为自动分离的人数。” | 文件格式和默认 200 MB 上限提示（实际值以后端配置为准）。 |
| 1:30–3:00 | 跳转处理页并等待 | “状态由 Redis + RQ Worker 驱动，按真实任务阶段推进：规范化、转录、对齐、说话人分离。” | `QUEUED → PREPROCESSING → TRANSCRIBING → ALIGNING → DIARIZING`，以及阶段耗时列表。 |
| 3:00–4:00 | 打开会议详情和完整转录 | “分离结果保留稳定原始标签；这段录音实际识别到几位说话人由任务结果给出。” | `diarization_status`、`speaker_count`、转录时间戳和标签。 |
| 4:00–4:45 | 将 `SPEAKER_00` 等标签映射为已知姓名 | “这是显示名称映射，不修改原始标签，因此可追溯。” | 转录显示姓名，原始 `speaker_label` 仍可见。 |
| 4:45–6:15 | 点击 AI 分析，查看摘要、结论、待办 | “仅此时才发送已保存的转录文本到模型服务；音频不作为该调用输入。” | 已生成的结构化结果、来源/模型信息（若界面显示）。 |
| 6:15–7:15 | 修改一条摘要或待办并保存，再查看审核差异 | “保存使用版本号，避免旧页面覆盖新审核结果。” | `analysis/audit` 的差异字段；可说明冲突会返回 409。 |
| 7:15–8:30 | 导出 Markdown 与 ICS，并导入 Outlook 测试环境 | “ICS 仅包含明确/人工确认日期的待办，并做了 UTF-8 BOM 与折行兼容处理。” | 下载文件、Outlook 正确显示中文事件。 |
| 8:30–9:30 | 返回处理详情和 API 文档 | “OpenAPI 文档实时来自运行中服务，可用于前后端对接和验收。” | `/docs`、`/openapi.json`、健康检查。 |

若需要展示失败恢复，可在独立测试会议上停止 Worker，确认任务进入 `FAILED` 并显示 `QUEUE_JOB_INTERRUPTED`，随后调用重试接口，确认原业务 job ID 复用且没有重复会议任务。演示完成后删除该临时会议。

## 4. 必须如实说明的边界

- 说话人分离的准确率随录音质量、重叠发言、噪声和模型变化而变化；成功状态表示流程成功产生标签，不表示身份必然正确。
- `SPEAKER_00`、`SPEAKER_01` 是录音内的稳定编号，并非跨会议的身份识别。
- `DEGRADED` 表示转录成功而说话人分离未完成；不得称为“分离已完成”。
- 若本次分析没有带明确或人工确认截止时间的待办，ICS 返回 `409 NO_EXPORTABLE_ACTION_ITEMS` 是设计行为，不是编码故障；应演示 Markdown 导出或先补充可确认日期再导出 ICS。
- 第六阶段起，生产任务通过 Redis + RQ 调度，Windows Worker 默认使用兼容 RQ 2.6.x 的 `rq.worker.SimpleWorker`；Linux/macOS 使用 `rq.worker.SpawnWorker`。演示前需先启动 Redis 和 Worker；Redis 不可用时上传会返回 `QUEUE_UNAVAILABLE`，不会显示为已排队。
- 受控 Gold Standard 的指标用于回归验证，不能代表所有真实会议的生产准确率。

## 5. 演示故障预案

| 现象 | 处理方式 | 不应采取的做法 |
| --- | --- | --- |
| `/health/ready` 失败 | 检查 MySQL 服务及 `backend/.env/meetingmind.env` 的配置字段，不显示其值。 | 在屏幕共享时打开或复制密钥文件。 |
| 分离结果为 `DEGRADED` | 说明降级设计：转录可继续使用，展示黄色警告和人工姓名映射。 | 把默认 `SPEAKER_00` 说成自动分离成功。 |
| AI 分析不可用 | 先演示本地转录、分离、映射和导出；检查本机模型配置。 | 以 Mock 结果冒充真实模型输出。 |
| ICS 没有事件 | 检查待办是否存在 `EXPLICIT` 或 `CONFIRMED` 截止时间。 | 修改文本文件编码后再声称为系统输出。 |
| 前端无法请求 API | 确认 Vite 代理和 `http://127.0.0.1:8000/api/v1/health`。 | 直接改前端为 Mock 模式作为验收替代。 |

## 6. 演示结束后的清理

若演示使用临时音频或测试会议，应在确认导出结果后通过会议列表删除该会议，或调用：

```powershell
Invoke-WebRequest -Method Delete http://127.0.0.1:8000/api/v1/meetings/<meeting_id>
```

这会删除关联数据库记录和本地会议文件。不要删除真实业务会议。
