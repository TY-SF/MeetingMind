# 第七阶段开发说明：发布级验收与质量加固

**开始日期：2026 年 9 月 13 日｜当前记录：2026 年 9 月 17 日**

## 阶段目标

第六阶段已经完成核心异步处理能力。第七阶段不再盲目增加业务功能，而是从“用户上传一段音频后，系统是否可观察、可恢复、可验证、可发布”出发，把现有能力固化为可重复的发布门禁。

本阶段采用以下判定原则：

1. 运行状态必须有明确证据，不能仅凭进程窗口判断服务正常。
2. 队列不可用时不能伪装成已排队；Worker 缺失时必须可诊断。
3. 失败、中断、重试和删除必须保持数据库、本地文件与队列状态一致。
4. 自动检查必须可重复执行，并且不能打印密钥、Token、密码、完整转录或模型响应。
5. 文档中的数字必须注明检查日期；历史结果不能冒充当前结果。

## 已完成工作

### 1. 修复发布前检查脚本

`scripts/pre_release_check.ps1` 原先存在 PowerShell 语法错误：OpenAPI 路径数组中混入了字面量 `` `n ``，导致脚本在真正检查前无法解析。现已修复，并增加：

- Docker Compose 配置校验；兼容 `docker-compose` 独立命令和 `docker compose` 插件；
- Redis/RQ Worker 健康检查，要求 Redis 为 `ok`、Worker 在线且队列状态为 `ready`；
- `-SkipInfrastructure`、`-SkipLiveServer`、`-SkipFrontend` 明确跳过开关；
- `-ReportPath` 生成不含敏感值的 JSON 检查报告；
- OpenAPI 重试接口路径校验恢复正常。

### 2. 当前可重复检查命令

```powershell
cd D:\MeetingMind
.\scripts\pre_release_check.ps1 -ReportPath .\data\release-check\latest.json
```

只在服务尚未启动时进行代码、迁移、依赖和 Gold Standard 检查：

```powershell
.\scripts\pre_release_check.ps1 -SkipLiveServer -ReportPath .\data\release-check\offline.json
```

只在没有 Docker 的环境中明确跳过 Compose 校验：

```powershell
.\scripts\pre_release_check.ps1 -SkipInfrastructure -SkipLiveServer
```

### 2. 完成真实运行态与故障恢复验收

在 Docker Desktop 运行的 MySQL 8.4 与 Redis 7.4 环境中完成了以下验收：

- 应用通过项目根目录 `.env.compose` 读取 Docker MySQL 配置；后端环境文件中的旧本机 `3306/root` 配置不会覆盖 Compose 配置；
- API、MySQL、Redis 和 RQ Worker 均处于可观测的健康状态；
- 使用获授权的真实中文音频完成上传、WhisperX 转录与对齐、pyannote 说话人分离、AI 分析和 Markdown 导出；
- 强制中断真实 RQ 任务后，任务进入 `FAILED`，错误码为 `QUEUE_JOB_INTERRUPTED`，阶段事件为 `TRANSCRIBING:INTERRUPTED`；重试成功复用原业务 job ID，未产生重复业务任务；
- 本轮临时会议的数据库记录和本地目录已删除；Redis 中已确认完成任务的旧 `started` 索引已清理。

### 3. 补强配置回归测试与发布材料

- 增加 Docker Compose 配置覆盖旧本地 MySQL 配置、进程环境变量优先级和相对配置文件路径的回归测试；

## 阶段结论与剩余发布门槛

第七阶段的核心自动验收、真实链路验收和故障恢复验收已完成，可以作为本地单机发布候选。仍不能宣称面向生产环境的全部门槛已经完成：

1. Outlook Classic 已于 2026 年 9 月 17 日使用无真实会议数据的 ICS 样本完成实际导入；中文和 Asia/Shanghai 时间转换正确；
2. HTTPS、反向代理、备份恢复、访问控制、日志保留和监控策略需要在实际部署环境完成；
3. 2026 年 9 月 17 日自动门禁已经对应到干净提交；后续代码或配置变更仍须重新执行完整检查。

## 非目标

本阶段不引入账户权限、实时转录、任务取消、多人协作或公网部署。这些能力仍属于设计文档中的后续 Roadmap。
