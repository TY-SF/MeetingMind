# 第八阶段开发说明：部署边界加固

**开始日期：2026 年 9 月 17 日**

## 阶段目标

第七阶段证明了系统在本地单机环境中可重复运行、恢复和验收。第八阶段从“服务一旦离开单一可信进程边界，什么必须先成立”出发，按以下顺序推进：

1. 访问控制；
2. HTTPS 与反向代理边界；
3. 数据库和运行文件备份/恢复；
4. 日志保留、监控和告警；
5. 容量、限流与正式多人身份系统。

## 1. 部署级访问令牌（已实现）

- 新增 `MEETINGMIND_API_TOKEN`，要求至少 32 个字符；
- 配置后，所有会议、任务、AI、导出、删除和队列健康接口都要求 Bearer 令牌；
- 存活、就绪、认证状态和 OpenAPI 文档保持公开，以支持编排和接入；
- 使用恒定时间比较，401 返回稳定错误码和 `WWW-Authenticate: Bearer`；
- OpenAPI 自动声明 `BearerAuth`，Swagger UI 可使用 Authorize；
- CORS 显式允许 `Authorization` 请求头；
- 前端只在当前浏览器会话中保存令牌，401 时提示重新输入；
- 发布检查从本地密钥文件读取令牌用于队列检查，但不打印令牌；
- 新增后端访问控制、OpenAPI、安全长度和 CORS 回归测试，以及前端令牌注入/轮换测试。

详细边界见 `docs/访问控制与部署边界.md`。

## 2. 本机 HTTPS 与反向代理边界（已实现）

- 新增固定版本 Caddy 的 `edge` Compose profile，只绑定本机回环端口；
- 使用内部 CA 为 `https://localhost:8443` 提供真实 TLS 握手，HTTP 端口正确 308 跳转；
- 同源提供 Vue 生产构建，并代理 API、Swagger、ReDoc 和 OpenAPI；
- 增加 CSP、nosniff、防嵌入、Referrer/Permissions Policy 和请求体上限；
- FastAPI 业务响应增加 `Cache-Control: no-store` 等基础安全头；
- 提供不含内部 CA 的生产 Caddy 示例，默认只代理回环 API并启用 HSTS；
- 增加启动、停止、配置验证脚本，并把 HTTPS 运行态检查纳入发布门禁；
- 已验证无令牌 HTTPS 请求返回 401、正确令牌返回 200，HTTP 正确跳转到带端口的 HTTPS 地址。

详细说明见 `docs/HTTPS与反向代理.md`。

## 安全定位

当前能力是单一部署令牌，只回答“请求是否来自获准客户端”，不回答“是谁、能访问哪条会议”。因此它适合单人设备或小范围受控环境，是正式公网身份系统之前的最小防线，不应被描述为多用户认证授权。

## 后续顺序

下一项是可恢复验证的数据库与 `data/meetings` 备份方案：

- 在同一恢复点同时覆盖 MySQL 元数据和会议文件；
- 备份过程不得记录密钥、完整转录或模型响应；
- 恢复必须在隔离目录/数据库中演练，而不是只证明“文件被复制”；
- 明确保留周期、加密、校验、失败告警和删除数据在备份中的生命周期。

真实公网域名、可信证书和防火墙验收仍属于目标部署环境的人工门槛。
