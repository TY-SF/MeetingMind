# 第六阶段开发说明

更新时间：2026 年 9 月 12 日。

## 阶段目标与完成情况

第六阶段的目标是把“单机可跑的音频处理程序”提升为具备队列、失败恢复、可观测性和部署基础设施的本地服务。以下能力均已实现：

1. **Redis + RQ 调度**：上传接口在 Redis 可用时创建持久化 RQ 任务；不会把 Redis 故障伪装成“已排队”。
2. **Windows Worker 兼容**：RQ 2.6.x 的 `SpawnWorker` 会在 Windows 调用不存在的 `os.wait4`。因此 Windows 默认运行 `rq.worker.SimpleWorker`，Linux/macOS 仍使用 `SpawnWorker`。两者均独立于 FastAPI 进程。
3. **Docker Compose**：提供 MySQL 8.4 与 Redis 7.4 定义，并验证 Redis 容器健康运行。
4. **正式重试 API 与界面操作**：`POST /api/v1/jobs/{job_id}/retry` 仅允许失败任务重新进入队列；处理页提供“重新处理”按钮。
5. **同会议任务互斥**：`0007_one_job_per_meeting` 为业务任务增加会议唯一约束，重试复用同一业务任务记录。
6. **WhisperX 对齐**：主链路按“预处理 → 转录 → 词级对齐 → 说话人分离”运行。
7. **媒体预检**：上传过程中计算 SHA-256，使用 `ffprobe` 校验真实音频流、时长与稳定错误码。
8. **AI 稳定性**：普通调用最多两次；仅无效结构化输出额外进行一次 JSON 修复调用。
9. **可观测性**：JSON 日志包含 `X-Request-ID`；新增 `GET /api/v1/health/queue` 显示 Redis、Worker、等待队列、执行队列和中间队列状态。
10. **Worker 中断恢复**：RQ 失败回调与 API 启动/周期性对账会将遗留业务任务转为 `FAILED`，关闭当前阶段事件为 `INTERRUPTED`，并提供稳定错误码 `QUEUE_JOB_INTERRUPTED` 或 `QUEUE_JOB_FAILED`。用户可随后重新处理。
11. **删除补偿**：本地文件删除失败时保留数据库记录并返回 `FILE_DELETE_FAILED`。

## 本机启动

### 1. 启动基础设施

```powershell
cd D:\MeetingMind
docker compose --env-file .env.compose up -d redis
```

本项目当前也可继续使用已存在的本机 MySQL 8；若需要 Docker MySQL，则执行：

```powershell
docker compose --env-file .env.compose up -d mysql redis
```

### 2. 配置后端环境

在 `D:\MeetingMind\backend\.env\meetingmind.env` 中确认：

```env
REDIS_URL=redis://127.0.0.1:6379/0
RQ_QUEUE_NAME=meetingmind
MEETINGMIND_QUEUE_BACKEND=rq
RQ_STALE_JOB_SECONDS=300
RQ_RECONCILIATION_INTERVAL_SECONDS=30
```

### 3. 分别启动 API 与 Worker

```powershell
cd D:\MeetingMind
$env:PYTHONPATH = "D:\MeetingMind\backend"
backend\.venv\Scripts\alembic.exe -c backend\alembic.ini upgrade head
backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

另开终端运行 Worker：

```powershell
cd D:\MeetingMind
.\scripts\start_rq_worker.ps1
```

如果需要 Worker 在关闭该终端后仍保持运行，使用后台启动器：

```powershell
.\scripts\start_rq_worker_background.ps1
```

日志在 `D:\MeetingMind\data\logs\rq-worker.stdout.log` 与 `rq-worker.stderr.log`。

## 队列诊断

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/health/queue
```

正常结果应包括：

```json
{
  "status": "ready",
  "redis": "ok",
  "worker_online": true,
  "worker_count": 1
}
```

若 `worker_online` 为 `false`，处理页面会提示启动 Worker；若 Worker 在处理中退出，最长在 `RQ_STALE_JOB_SECONDS` 加对账间隔后，任务会转为失败并允许重新处理。
