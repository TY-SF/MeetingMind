# 访问控制与部署边界

> 更新日期：2026 年 9 月 17 日。当前实现提供部署级 Bearer 访问令牌，不等同于用户账户、角色权限或多租户隔离。

## 第一性原则

只要服务能够从另一台设备访问，“知道地址”就不能被当作授权。MeetingMind 中的录音、转录、摘要和导出属于业务数据，因此业务 API 在受控本机以外运行时必须具备最小访问边界。

当前采用单一部署令牌，目标是：

- 阻止未持有令牌的客户端读取、上传、修改或删除会议数据；
- 不把后端令牌写进前端构建产物、URL、日志或版本库；
- 保留无需凭据的存活/就绪探针；
- 为后续反向代理、HTTPS 和正式身份系统提供清晰迁移边界。

## 配置

在被 Git 忽略的 `backend/.env/meetingmind.env` 中设置：

```env
MEETINGMIND_API_TOKEN=至少32个字符的高熵随机值
```

可用本机 Python 生成随机值：

```powershell
backend\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

生成结果属于密钥，只能写入本地环境文件或密钥管理系统，不应粘贴到聊天、工单、截图或提交记录中。少于 32 个字符时，后端拒绝启动。

未配置 `MEETINGMIND_API_TOKEN` 时，令牌中间件保持禁用，便于隔离的自动化测试；当前发布门禁要求真实本地发布配置必须设置有效令牌。

## 受保护范围

配置令牌后，除以下公开端点外，所有 `/api/v1/*` 业务接口都要求：

```http
Authorization: Bearer <MEETINGMIND_API_TOKEN>
```

公开端点：

- `GET /api/v1/health`：进程存活探针；
- `GET /api/v1/health/ready`：数据库就绪探针；
- `GET /api/v1/auth/status`：只返回是否启用认证以及当前请求是否已认证，不返回令牌；
- `/docs`、`/redoc`、`/openapi.json`：API 契约，不包含会议业务数据或密钥。

`GET /api/v1/health/queue` 包含运行队列信息，因此属于受保护接口。

错误语义：

| 状态 | 错误码 | 含义 |
| --- | --- | --- |
| 401 | `ACCESS_TOKEN_REQUIRED` | 未提供 Bearer 令牌 |
| 401 | `ACCESS_TOKEN_INVALID` | 令牌错误、已轮换或格式不正确 |

响应同时包含 `WWW-Authenticate: Bearer`。令牌使用恒定时间比较，日志不会记录 Authorization 请求头。

## 前端行为

- 页面收到 401 时会提示输入访问令牌；顶部“访问令牌”按钮也可主动打开输入框。
- 令牌只保存在浏览器 `sessionStorage`，不会进入前端构建变量或永久 `localStorage`。
- 关闭对应浏览器标签页/会话后需要重新输入。
- 后端轮换令牌后，旧令牌请求会收到 `ACCESS_TOKEN_INVALID`；前端清除旧值并提示重新输入。

浏览器存储仍会受到同源脚本影响，因此必须继续控制前端依赖和 XSS 风险。部署级令牌不能替代 HTTPS：在非本机网络上传输时，必须先由反向代理终止 TLS。

## 命令行示例

不要把令牌直接写进命令历史。可从当前进程环境读取：

```powershell
$headers = @{ Authorization = "Bearer $env:MEETINGMIND_API_TOKEN" }
Invoke-RestMethod http://127.0.0.1:8000/api/v1/meetings -Headers $headers
```

如果令牌只存在于后端环境文件，发布检查脚本会在内存中读取并使用，但不会输出其值。

## 轮换与撤销

1. 生成新的高熵令牌；
2. 更新后端环境或密钥管理系统；
3. 重启 API；
4. 旧令牌立即失效，客户端重新输入新令牌；
5. 确认日志、终端历史和沟通渠道中没有泄露旧值。

当前实现不支持多枚并行令牌，因此无零中断双令牌轮换窗口。

## 当前明确不提供

- 用户注册、登录、密码重置；
- 用户身份、角色或资源级权限；
- 多租户隔离；
- 单用户审计归属；
- 令牌过期时间、刷新令牌或服务端会话；
- 防暴力破解的速率限制；
- HTTPS、反向代理和公网安全组。

如果需要多人使用或公网部署，应在反向代理/身份提供商层增加正式 OIDC/OAuth2 登录和用户授权，并保留本令牌作为内部服务边界或替换为短期服务凭据。
