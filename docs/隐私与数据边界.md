# 隐私与数据边界

> 适用范围：MeetingMind 当前的本地单机版本。本文说明系统实际处理哪些数据、数据会去哪里，以及使用者必须承担的确认责任。它不是法律意见。

## 核心原则

1. **最小外发**：原始音频只在本机保存和处理，不由 AI 分析接口发送给模型服务。
2. **显式触发**：只有使用者主动执行“AI 分析/重新生成”，系统才会把转录相关数据发送到已配置的模型服务。
3. **无自动脱敏**：系统当前不会自动识别或移除姓名、电话、地址、商业秘密等敏感信息。
4. **授权在先**：只应上传使用者有权处理的录音；上传和每次 AI 分析都必须进行显式确认。

## 数据流

| 阶段 | 处理的数据 | 目的地 | 是否外发 |
| --- | --- | --- | --- |
| 上传与保存 | 原始 MP3、WAV、M4A | 本机 `data/meetings/<meeting_id>/source/` | 否 |
| FFmpeg / WhisperX / pyannote | 原始或规范化音频、转录片段、说话人标签 | 本机进程与 `data/meetings/<meeting_id>/` | 否 |
| AI 分析 | 带时间戳的转录文本、说话人标签、会议发生时间和会议背景 | `LLM_BASE_URL` 指向的已配置模型服务 | 是，仅在显式确认后 |
| AI 分析排除项 | 原始音频和规范化音频 | 不发送到模型服务 | 否 |
| 脱敏 | 当前没有自动脱敏步骤 | 使用者必须在外发前自行判断和处理 | 不适用 |

`LLM_BASE_URL` 可以指向 OpenAI，也可以指向兼容 OpenAI API 的其他服务。使用自定义地址时，该服务可能由第三方运营；其数据保留、训练、地域和合规政策不由 MeetingMind 控制，应由部署者单独核验。

## 显式确认

### 上传录音

`POST /api/v1/meetings` 必须在 `multipart/form-data` 中包含：

```text
data_processing_confirmed=true
```

该确认表示调用方：

- 已获得处理该录音所需的授权；
- 理解音频会保存在本机并在本机处理；
- 理解系统不会自动脱敏；
- 理解后续主动调用 AI 分析时，转录相关数据可能发送到外部模型服务。

缺失或为 `false` 时，接口返回 `422 DATA_PROCESSING_CONFIRMATION_REQUIRED`，且不会保存上传文件。

### AI 分析与重新生成

每次 `POST /api/v1/meetings/{meeting_id}/analysis` 都必须发送：

```json
{
  "analysis_data_confirmed": true
}
```

该确认只对当前请求有效。缺失或为 `false` 时，接口返回 `422 ANALYSIS_DATA_CONFIRMATION_REQUIRED`，不会调用模型服务。重新生成会替换当前 AI 草稿，因此前端会同时提示数据外发和覆盖风险。

## 密钥与访问控制

- `OPENAI_API_KEY` / `LLM_API_KEY`、`HF_TOKEN`、数据库密码等只应保存在后端本机的环境文件或进程环境中，不应进入前端变量、请求体、截图、日志或版本库。
- 当前版本可用 `MEETINGMIND_API_TOKEN` 为业务 API 启用单一部署级 Bearer 访问控制；它不是用户身份、角色权限或租户隔离。
- 前端只在当前浏览器会话中保存该令牌；令牌不会进入构建变量或永久本地存储。
- 如需向多人或公网提供服务，仍必须增加正式身份授权、HTTPS、网络边界、审计、速率限制和密钥管理。详见 `docs/访问控制与部署边界.md`。

## 删除、备份与日志

- 删除会议会尝试删除会议数据库记录及其 `data/meetings/<meeting_id>/` 本地目录；删除是不可恢复操作。
- 操作系统备份、磁盘快照、数据库备份或手工复制可能继续保留数据，MeetingMind 不会自动清除这些外部副本。
- 应用日志用于记录请求 ID、阶段、耗时和错误；发布检查禁止输出密钥、完整转录或完整模型响应。部署者仍应限制日志访问并设置合理的保留期限。
- 导出的 Markdown、ICS 以及使用者另存的文件不受会议删除操作管理，需要由使用者自行删除。

## 使用前检查

在上传前确认：

- 录音来源合法，参会人告知与同意满足适用规则；
- 本机磁盘、数据库、备份和日志的访问范围可接受；
- 会议内容适合由当前设备处理。

在 AI 分析前确认：

- 转录文本与会议背景中没有不应外发的信息，或已由使用者手工处理；
- `LLM_BASE_URL` 和模型服务运营方符合组织要求；
- 已了解该服务的数据保留、训练使用、地域和安全政策。
